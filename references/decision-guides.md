# 决策指南：对比与选型报告的分支判定

**何时读取**：报告涉及比较、选型、采购、采纳、部署或架构选择时读取。此类报告必须包含分支决策指南，否则视为结构不完整。

**用途**：把分析转成读者一分钟内能执行的确定性判断，而不是把加权评分表丢给读者自行解读。

## 1. 先找会改变结论的硬门槛

从能够直接排除某个选项的约束开始，而不是从界面美观、社区热度等软偏好开始。常见硬门槛：

- 法律、政策、授权或许可证限制；
- 是否允许无人值守执行不可逆操作；
- 数据、凭据或部署边界要求；
- 必须提供的验收证据或可审计性；
- 最低规模、延迟、可靠性或预算阈值；
- 组织是否具备运维与维护能力。

只要硬门槛能改变推荐结果，就必须放在评分表之前，作为分支的第一个问题。

## 2. 构建分支流程

- 使用 3–7 个决策节点，每个节点只问一个可以明确回答的问题。
- 分支必须互斥，不要出现「部分满足」「视情况而定」这类无法执行的选项。
- 每条路径都必须终止于以下四种结果之一：具名推荐方案、选择前的先决动作、回退方案、明确的拒绝或停止条件。
- 决策指南放在背景/引言之后、详细发现之前；分支问题本身用短标签，判断依据与来源放在相邻段落里说明。报告中的章节标题按 `references/report-template.md` 使用 `## 决策指南`，最后一个子节固定为 `### 选择结果`。
- 选项名称在决策指南、正文建议与结论中必须完全一致。

分支流程用 Markdown 编号列表与缩进表达，例如：

```markdown
### 分支决策指南

1. 是否允许将账号凭据交给第三方托管？
   - 否 → 推荐自托管方案 A；若团队无运维能力 → 先补运维能力，暂停选型
   - 是 → 进入第 2 题
2. 是否要求无人值守执行不可逆操作？
   - 是 → 排除方案 B，推荐方案 C 并强制人工复核
   - 否 → 推荐方案 B
```

## 3. 不可补偿风险

加权评分不能抵消硬性禁止条件。更强的自动化、更低的成本或更高的流行度，都不能补偿缺失授权、许可证不兼容或最终状态不可验证。先写硬门槛分支，再列评分表；评分表只能用于硬门槛之后的同层比较。

## 4. 文字回退

本技能交付 Markdown 与 HTML，决策指南必须用语义化 Markdown 表达，不依赖需要额外渲染器的语法或外部资源。分支流程之后必须紧跟一个 `### 选择结果` 小节，用表格或列表把每个终端建议重复一遍：

```markdown
### 选择结果

| 读者场景 | 终端建议 |
| --- | --- |
| 不允许第三方托管凭据，且有运维能力 | 方案 A |
| 不允许第三方托管凭据，但无运维能力 | 先补运维能力，暂不选型 |
| 允许托管，且不需要无人值守 | 方案 B |
| 需要无人值守执行不可逆操作 | 方案 C + 人工复核 |
```

要求：文字回退覆盖分支流程中的每一个终端结果，不遗漏、不改名。
