# 研究报告模板（report-template）

最终报告统一保存为 `research_report_<topic_slug>.md`，写入当前工作目录。下面是结构模板与写作要求，按实际内容替换方括号部分。

## 字数区间

按查询类型控制篇幅，宁可精炼也不要注水：

- 直接型（straightforward）查询：500 至 1000 字。
- 深度优先（depth-first）查询：1500 至 3000 字。
- 广度优先（breadth-first）查询：2000 至 4000 字。

## 结构模板

```markdown
# [报告标题：清楚说明本研究回答什么问题]

## 执行摘要

[2 至 4 句话，独立成立地总结关键发现与主要结论。读者只读这段也应能抓住核心答案。不要在这里写「本文将……」之类的预告。]

## 背景

[如与主题相关，简要说明研究背景、为什么这个问题重要、关键定义或范围。若问题本身已经非常明确，可省略或压缩到一两段。]

## [正文第一节：描述性小标题]

[按逻辑呈现研究结果。包含具体数据、数字、日期、名称和事实；每个关键事实尽量有来源支撑。以段落为主，不要堆砌项目符号。]

## [正文第二节：描述性小标题]

[继续展开其他维度的发现。可用多个描述性小标题组织，标题要能概括该节内容。]

## 分析综合

[复杂问题适用：比较不同视角或方法，识别模式与矛盾，跨来源综合，说明证据强弱。简单问题可省略本节。]

## 结论

[清楚、直接地回答用户最初的问题，呼应原始需求；不要引入正文没有支持的新事实。]

## 局限

[说明数据、时间范围、来源可得性等方面的局限，以及哪些方向值得进一步研究。若无明显局限，可简要说明研究边界。]

## References

1. [来源标题](https://example.com/actual-url)
2. [来源标题](https://example.com/actual-url)
3. [来源标题](https://example.com/actual-url)
```

## 写作要求

报告默认使用清晰的小标题和段落来组织信息，少用项目符号。只有在用户明确要求列表或排名、或者对比表格确有必要（如价格、功能、规格）时才使用列表或表格；表格前要有上下文引入，表格后要有分析解读。

报告必须准确、具体，尽量包含数字、日期、名称等可量化信息，避免「很多」「显著」「近期」这类模糊表述。存在多种观点或来源冲突时要客观呈现，说明取舍依据，不要把推测写成事实。严格禁止 emoji。

References 必须是编号列表，每条都用 `[标题](URL)` 的 Markdown 链接格式，确保可点击；不得列出没有 URL 的来源，也不得编造或补全链接，只列真实访问过的来源。
