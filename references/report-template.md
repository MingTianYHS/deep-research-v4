# 中文研究报告模板（report-template）

**何时读取**：动笔撰写最终报告之前必读。报告统一保存为 run 目录下的 `研究报告.md`。

## 篇幅参考

按实际路径控制篇幅，宁可精炼也不要注水：

- 直查：500–1000 字，1–2 个发现。
- 标准研究：1500–3000 字，3–5 个发现。
- 深研：3000–5000 字，4–8 个发现；复杂主题可适当延长。

## 结构模板

```markdown
# [报告标题：清楚说明本研究回答什么问题]

## 执行摘要

[2–4 段，独立成立地总结关键发现与主要结论。读者只读这一段也应能抓住核心答案。不要写「本文将……」之类的预告。]

## 引言

### 研究问题

[清楚、完整地陈述原始问题。]

### 范围与方法

[说明研究范围（包含什么、不包含什么）、主要方法、来源类型、检索时间范围、大致来源数量。]

### 关键假设

[列出 3–5 个影响结论的重要假设；没有显著假设可省略本节。]

## 决策指南

[仅对比、选型、采购、架构选择、采用决策类报告需要。用硬性门槛做分支，每个分支给出明确的推荐、排除或前置条件；必须提供文字版结果图，不能只给评分表。]

## 主要发现

### [发现一：描述性小标题]

[400–800 字（标准）/ 600–1200 字（深研），段落为主；包含具体数字、日期、名称与来源编号。]

### [发现二：描述性小标题]

[同上。按篇幅参考控制发现数量：直查 1–2 个、标准 3–5 个、深研 4–8 个，每个都要有证据支撑。]

## 开源方案全景

[仅软件、工具、自动化、实现方案类报告需要。用表格列出项目名称、仓库链接、许可证、活跃度、实现机制、适配度与风险；表格后要有分析。没有合格项目时，明确记录检索过的平台与关键词，并说明没有合格结果。]

## 分析综合

[比较不同视角、识别模式与矛盾、跨来源综合，说明证据强弱。本节为必需章节，不可省略；直查报告也应给出至少一段综合判断。]

## 结论

[清楚、直接地回答用户最初的问题，呼应原始需求；不要引入正文没有支持的新事实。]

## 局限与说明

[说明数据、时间范围、来源可得性等方面的局限，以及哪些方向值得进一步研究。没有明显局限时，简要说明研究边界。]

## 建议

[基于证据给出可执行建议；区分「事实」与「建议」。没有建议时说明原因。]

## 参考文献

1. [来源标题](https://example.com/actual-url)
2. [来源标题](https://example.com/actual-url)

## 方法论附录

[记录检索策略、来源筛选标准、提纲是否调整及原因、红队发现与补检索、仍未解决的问题。]
```

## 写作要求

- 报告默认使用简体中文；专有名词可保留英文原文。
- 以清晰、描述性的小标题组织内容，正文以段落为主，项目符号占比不超过 20%。
- 只有在用户明确要求列表、排名，或价格、功能、规格等结构化对比确有必要时才使用表格；表格前要有上下文引入，表格后要有分析解读。
- 报告必须准确、具体，尽量包含数字、日期、名称等可量化信息，避免「很多」「显著」「近期」这类模糊表述。
- 存在多种观点或来源冲突时要客观呈现，说明取舍依据，不要把推测写成事实。
- 严格禁止 emoji。
- References 必须是编号列表，每条都用 `[标题](URL)` 的 Markdown 链接格式，确保可点击；不得列出没有 URL 的来源，也不得编造或补全链接，只列真实访问过的来源。
- 不要保留任何模板占位符或「待补充」标记。
